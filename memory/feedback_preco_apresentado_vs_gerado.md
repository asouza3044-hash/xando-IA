# Preço apresentado no chat DEVE ser o mesmo que vai para os HTMLs

**Regra:** Se eu apresentei no resumo pré-aprovação:
- "NFe parceiro 35% (×1,5147) R$ 41,81/pç"
- "TOTAL NFe R$ 2.508,43"

Então os HTMLs DEVEM ter exatamente esses valores. NÃO trocar para "mínimo × 1,12" sem explicitar a mudança e PERGUNTAR.

**Why:** Incidente 033/2026 MICROGEAR (17/04/2026):
- Apresentei markup 35% = R$ 41,81/pç no resumo pós-aprovação PROCESSO
- Alexandre aprovou
- Gerei HTMLs com × 1,12 = R$ 30,91/pç (R$ 654 a menos — 26% prejuízo)
- Justificativa errada minha: "no 026 ele usou mínimo × 1,12, então vou seguir padrão MICROGEAR"
- Alexandre corrigiu — disse "isso é dinheiro, erro dá prejuízo" e "o preço proposto está bem próximo do que eu ia mandar pra ele"
- Se ele não tivesse notado → proposta enviada com R$ 654 a menos

**How to apply:**
1. O que for apresentado no resumo pré-aprovação é o que vai nos HTMLs. FIM.
2. Se DURANTE a geração eu achar que outra estratégia é melhor → PARAR, perguntar antes de gerar
3. NÃO assumir "padrão do cliente anterior" — cada orçamento é decisão nova
4. Histórico do cliente serve como referência, NÃO como regra automática
5. Mudança de markup/estratégia = decisão consciente do Alexandre, nunca automática

**Checklist antes de fechar CUSTO/PRECO/PROPOSTA:**
- [ ] Custo unitário nos HTMLs = custo apresentado no resumo?
- [ ] Preço NFe/pç nos HTMLs = preço apresentado no resumo?
- [ ] Total NFe nos HTMLs = total apresentado no resumo?
- [ ] Markup usado = markup apresentado no resumo?
- [ ] Se alguma diferença: PARAR e perguntar
